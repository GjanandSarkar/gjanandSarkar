# Subscription Architecture (Phase 10)

## Overview
Phase 10 overhauls the Recurring Subscription experience to establish it as a primary pillar of the Gjanand Sarkar business model. The primary focus is shifting the UX away from a generic settings menu and transforming it into a "Subscription Hub".

## Component Architecture
1. **Subscription Hub** (`/subscribe/page.tsx`): 
   - Fetches and orchestrates all subscription data.
   - Replaces the generic list view with specialized modules.
2. **Upcoming Deliveries Module** (`UpcomingDeliveries.tsx`): 
   - A visual representation of the next 3 days of deliveries across all active subscriptions. 
   - **Simulated Visualization:** Currently, true delivery frequencies (Daily, Alternate Day, Weekly) are not supported by the database schema. This module simulates the "next 3 days" by assuming a daily delivery pattern to give users a sense of the layout, but explicitly marks itself as a "Demo View" so it isn't confused for an actual real-time schedule.
3. **Subscription Card** (`SubscriptionCard.tsx`):
   - A robust, interactive component replacing the old list item.
   - Extracts "Pause", "Resume", and "Modify" actions from the hidden dropdown and surfaces them directly on the card to improve discoverability and retention.
4. **Subscription Creation** (`/subscribe/new/page.tsx`):
   - Overhauled visually to emphasize the premium nature of the service (A2 milk).
   - Dynamic pricing visualizes the 5% savings generated by selecting the Monthly plan over the Weekly plan.
5. **Subscription Skeleton** (`SubscriptionSkeleton.tsx`):
   - Custom animate-pulse state that exactly matches the shapes of the `UpcomingDeliveries` and `SubscriptionCard` components to prevent cumulative layout shift (CLS).

## Retention Strategy
1. **Pause vs Cancel**: To minimize churn, "Pause" is now a primary, sticky button on the active subscription card. "Cancel" has been intentionally pushed behind the `MoreHorizontal` 3-dot dropdown menu, adding just enough friction to encourage pausing instead of outright canceling.
2. **Delivery Confidence**: The `UpcomingDeliveries` module visually reinforces the value of the subscription, letting the user know precisely when they will receive their fresh milk.

## Backend Dependencies
This phase strictly relied on the existing API methods in `src/lib/api/subscriptions.ts`:
- `getUserSubscriptions`
- `pauseSubscription`
- `cancelSubscription`
- `submitModificationReport`
- `/api/subscriptions` route handler for creation and modifications.

No database migrations or new backend endpoints were created.

## Future Automation Notes
1. **Skip Delivery**: While the `UpcomingDeliveries` UI displays dates, there is currently no backend support for skipping a single delivery. If this feature is added to the backend, it can be easily hooked into the `UpcomingDeliveries` visual cards.
2. **Payment Integration**: The onboarding flow currently says "Pay ₹X to Subscribe", but it instantly provisions the subscription in Supabase. In the future, this needs to be wired to a real payment gateway (like Razorpay) before generating the subscription row.
